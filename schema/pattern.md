# Формат паттерна, версия 0.2

Файл `patterns/<id>.md`. В начале YAML-шапка, ниже свободный текст для людей.

Структура взята у Кристофера Александера («A Pattern Language», 1977): контекст, проблема, силы, решение, связи с другими паттернами. Паттерн ссылается на проблемы через теги, а не через P-ид: проблемы принадлежат проекту, паттерн переживает проект и переезжает в следующий.

```yaml
---
id: kebab-case-id
status: active | proposed | deprecated
solves: [теги из tags.yaml проекта]   # проблема, на которую отвечает паттерн
when:        # контекст: условия, при которых паттерн подходит
  - ...
avoid_when:  # когда не применять, даже если теги совпали
  - ...
forces:      # силы: что с чем конфликтует, и почему решение именно такое
  - pull: "что тянет в одну сторону"
    against: "что тянет в другую"
    resolved_by: "какое правило паттерна снимает конфликт"
related:     # связи с другими паттернами, все id должны существовать
  part_of: []    # паттерны крупнее, внутри которых этот живёт
  contains: []   # паттерны мельче, из которых этот собирается
  see_also: []   # соседние: часто применяются вместе или конкурируют
uses: [компоненты из components/index.yaml]
composition: [файлы из composition/]
---
```

Тело: суть паттерна, структура блока, правила контента, анти-паттерны, пример.

## Как писать силы

- Сила это реальное желание или ограничение: пользователя, компании (`invariants/`), контента, платформы. Не «хорошо бы».
- Если силы не конфликтуют, паттерн не нужен: хватит правила в `composition/`.
- У каждой силы есть `resolved_by`, и это правило должно встречаться в теле паттерна. Если правило снимает конфликт только наполовину, так и пишем.
- Силы из `invariants/` указываем ссылкой: `invariants/must_not`, `invariants/positioning.promise`.

`forces` и `related` нужны для `status: active`, для `proposed` опциональны. `scripts/check.py` предупреждает об активном паттерне без сил, падает на ссылке на несуществующий паттерн и предупреждает о несимметричной связи (A `contains` B, но у B нет `part_of: [A]`).
