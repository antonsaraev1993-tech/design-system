# AGENTS.md

Точка входа для любого агента (Claude, Codex, Cursor, свой скрипт). Всё знание о редизайне лежит в этом репозитории, внешний контекст не нужен.

## Что здесь

| Папка | Что это | Можно ли менять агенту |
|---|---|---|
| `invariants/` | Сущность бренда: то, что редизайн не меняет | Нет. Только читать |
| `problems/` | Проблемы, которые решает редизайн, на формальном языке (`schema/problem.schema.yaml`) | Нет. Предлагать новые через `status: proposed` |
| `patterns/` | Предпочитаемые интерфейсные паттерны этой системы | Нет. Предлагать новые через `status: proposed` |
| `composition/` | Правила компоновки: сетка, ритм, иерархия, плотность | Нет |
| `components/` | Каталог компонентов и токены, на которых они собраны | Нет |
| `tokens/` | Токены в формате DTCG, генерируются `scripts/build_tokens.py` из дизайн-системы | Нет. Не править руками |
| `decisions/` | Решения: какая проблема каким паттерном закрыта и почему | Да, это твой основной выход |

## Порядок работы

1. Прочитай `invariants/brand.yaml`. Всё, что там есть, считается ограничением для любого решения.
2. Возьми проблему из `problems/` со `status: open`.
3. Найди паттерн, у которого `solves` пересекается с `tags` проблемы и выполняются `when`. Проверь `avoid_when`.
4. Если подходящего паттерна нет, не придумывай решение молча. Создай черновик паттерна со `status: proposed` и укажи это в решении.
5. Собери решение только из компонентов `components/index.yaml` и правил `composition/`. Новые значения цветов, отступов, шрифтов запрещены: только токены.
6. Запиши решение в `decisions/` по шаблону `decisions/_template.md`.
7. Запусти `python3 scripts/check.py`. Решение без зелёной проверки не считается готовым.

## Чего не делать

- Не менять позиционирование, тон и фирменные элементы из `invariants/`.
- Не ссылаться на паттерны и компоненты, которых нет в репозитории.
- Не переписывать описания проблем под удобное решение.
- Пометки вида `[уточнить у клиента]` означают, что факта пока нет. Не заполняй их догадками.
